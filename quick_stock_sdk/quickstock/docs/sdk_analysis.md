# QuickStock SDK 两个版本功能分析

## 一、quick_stock 版本

### 1. 核心结构
- **目录结构**：简洁明了，分为 d（数据访问）、remote（远程数据源）、share（共享功能）三个子模块
- **客户端设计**：为不同数据类型提供独立客户端，如 TradeStockClient、TradeIndexClient 等
- **API 设计**：方法命名直观，参数简单，易于使用

### 2. 核心功能

#### 2.1 股票数据功能
- `get_all_stock()`：获取所有股票列表
- `minute(code)`：获取股票分钟数据
- `minute30(code, start=None, end=None)`：获取30分钟线数据
- `minute60(code, start=None, end=None)`：获取60分钟线数据
- `daily(code, start=None, end=None)`：获取日线数据
- `weekly(code, start=None, end=None)`：获取周线数据
- `monthly(code, start=None, end=None)`：获取月线数据

#### 2.2 指数数据功能
- 类似股票数据的时间序列数据获取（分钟线、日线、周线、月线）

#### 2.3 交易日期功能
- 提供交易日期相关查询

#### 2.4 概念数据功能
- 提供股票概念相关数据

### 3. 数据源支持
- 同花顺（tonghuashun）

### 4. 特点
- **优点**：结构简单，API直观，易于上手和维护
- **缺点**：功能单一，扩展性差，仅支持单一数据源，缺乏统一的错误处理和配置管理

## 二、release_config 版本

### 1. 核心结构
- **目录结构**：复杂分层设计，包括 core（核心功能）、models（数据模型）、providers（数据源）、services（服务层）、utils（工具类）
- **客户端设计**：单例客户端设计，提供统一入口
- **配置系统**：完整的配置管理，支持多种配置方式

### 2. 核心功能

#### 2.1 基础功能
- 客户端初始化和配置管理
- 日志系统
- 上下文管理器支持

#### 2.2 代码转换功能
- `normalize_code(code)`：标准化股票代码
- `convert_code(code, target_format)`：转换股票代码格式
- `parse_code(code)`：解析股票代码
- `validate_code(code)`：验证股票代码
- 批量代码处理功能
- 代码格式识别和自动修正

#### 2.3 数据获取功能
- **股票基础数据**：`stock_basic()`、`stock_detail()`
- **股票时间序列数据**：
  - `stock_daily()`：日线数据
  - `stock_minute()`：分钟线数据
  - `stock_weekly()`：周线数据
  - `stock_monthly()`：月线数据
- **指数数据**：
  - `get_index_basic()`：指数基础信息
  - `get_index_daily()`：指数日线数据
- **基金数据**：
  - `get_fund_basic()`：基金基础信息

#### 2.4 统计分析功能
- **涨跌分布统计**：`price_distribution_stats()`
- **涨停统计**：`daily_limit_up_stats()`

#### 2.5 数据源管理功能
- 多数据源支持（东方财富、同花顺、Baostock等）
- 数据源健康检查：`health_check()`、`test_connection()`
- 数据源统计信息：`get_provider_stats()`、`get_provider_health()`

#### 2.6 性能和监控功能
- 内存管理：`get_memory_stats()`、`optimize_memory_usage()`
- 性能监控和基准测试

### 3. 数据源支持
- 东方财富（eastmoney）
- 同花顺（tonghuashun）
- Baostock

### 4. 特点
- **优点**：功能丰富，支持多数据源，有完整的错误处理和配置管理，扩展性强
- **缺点**：结构复杂，代码量大，学习曲线陡峭，维护成本高

## 四、核心功能总结

### 1. 必须保留的核心功能
- 股票基础数据获取
- 股票时间序列数据获取（分钟线、日线、周线、月线）
- 指数数据获取
- 简单易用的API设计

### 2. 可以简化的功能
- 复杂的代码转换功能（保留基础转换即可）
- 过多的统计分析功能（保留核心统计即可）
- 复杂的性能监控和内存管理
- 过于复杂的配置系统

### 3. 可以优化的方向
- 保持 API 简洁易用的同时，提供适当的扩展性
- 支持多数据源，但简化数据源管理
- 提供统一的错误处理，但不要过于复杂
- 保持代码结构清晰，易于维护
